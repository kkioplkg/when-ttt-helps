# Manifest and transfer integrity

Two hash lists, because the staged copies are not byte-identical to what
the compute host produced --- and the difference is deliberate, so it is
recorded rather than papered over.

| file | what it hashes |
|---|---|
| `MANIFEST_source.sha256` | the 24 measurement files **as produced on the compute host**, hashed there before transfer |
| `MANIFEST_staged.sha256` | all 43 files **as they now sit in this directory**, the 19 that were never transferred included |

**Transfer integrity.** All 24 files were verified against
`MANIFEST_source.sha256` immediately after transfer: **24 / 24 matched, 0 mismatches, 0 missing.** The transfer itself was
lossless, and the check was re-run against the host before this directory
was written, not only at transfer time.

**Post-transfer transform.** 12 of the 24 files were then
path-sanitized: `meta.argv` recorded absolute paths from the compute host,
and a shippable artifact must not carry a path that resolves nowhere in an
extracted archive. The transform is textual and idempotent --- strip the
repository prefix, leaving repository-relative paths --- and it is the same
one the theory-closure suite applied, for the same reason. Those
12 files therefore hash differently in the staged manifest, by
design:

* `json/cifar100_resnet26ttt_s0.json`
* `json/cifar100_resnet26ttt_s1.json`
* `json/cifar100_resnet26ttt_s2.json`
* `json/cifar10_resnet26ttt_s0.json`
* `json/cifar10_resnet26ttt_s1.json`
* `json/cifar10_resnet26ttt_s2.json`
* `records/cifar100_ttt_rot_main_s1.json`
* `records/cifar100_ttt_rot_main_s2.json`
* `records/cifar10_ttt_mask_main_s1.json`
* `records/cifar10_ttt_mask_main_s2.json`
* `records/cifar10_ttt_rot_main_s1.json`
* `records/cifar10_ttt_rot_main_s2.json`

* **byte-identical to source: 12 / 24** --- the six
  crossed measurement matrices, the frozen episode manifest and the five
  analysis outputs. Those files carry no path field, so nothing needed
  doing to them.
* **path-sanitized: 12 / 24** --- the six source-model
  evaluation records and the six exposed adaptation records.
* **measurements altered: 0.** The transform touches string values that are
  paths and nothing else. Every number in every file is what the run wrote.

**Files that were never transferred (19).** They have no row in
`MANIFEST_source.sha256` because they were not produced on the compute
host:

* `RESULTS.md`, `DESIGN.md`, `DESIGN_REVIEW_ROUNDS.md` --- the design, its
  adversarial review and the results report, all authored here.
* `json/sm_equivalence.json` --- the proof that this suite's statistics port
  reproduces the published `f14_deltafeat_check.json` audit. It is computed
  from the *published* record and was run here before any fresh number
  existed, which is the whole point of it.
* `SEEDMATCH_RECORDS_MANIFEST.json` --- generated by
  `experiments/ttt/is_fresh/f42_seedmatch_records_manifest.py` from the side
  archive it describes.
* `code/` --- the 13 measurement, analysis and orchestration
  scripts, copied from `experiments/ttt/seedmatch/`, which is where they ran
  from and which remains their master copy.

**One transform was applied to the code, and it is the publish transform,**
**not a correction.** Four of the scripts anchored themselves on the compute
host's repository root as a hard-coded default. In the shipped copy that
default is removed: the root now comes from `$TTT_ROOT` (or `--ttt-root`)
with no fallback, so the script either runs against the reader's own tree or
says so, rather than silently resolving to a path that does not exist. The
files are

* `code/chain.sh`
* `code/launch_train.sh`
* `code/runner.sh`
* `code/make_jobs.py`

and the master copies under `experiments/ttt/seedmatch/` are left exactly as
they ran. Nothing else in any script was changed --- no measurement, no
statistic, no default that affects a number.

**A third transform, and the smallest.** Five documents and two scripts
described the objection this experiment answers by attributing it to an
anonymous reader. A package meant to be read cold does not attribute a
technical criterion that way, so those seven sentences now name the
objection instead of the person; the objection itself is unchanged and so
is every statement about it. The substitution is null in meaning and was
applied to the master copies under `experiments/ttt/seedmatch/` as well, so
the shipped and master scripts do not diverge for a second reason.

To re-verify the staged tree:

```
sha256sum -c MANIFEST_staged.sha256
```

**What that reports depends on which copy of this directory you are in,**
and the difference is by construction rather than by accident:

| where | rows that verify | rows that report a missing file |
|---|---:|---|
| the source tree | 43 of 43 | none |
| an extracted `release_archive.zip` | 30 of 43 | the 12 raw records, which are the side archive, and the design-audit transcript, which does not ship |
| the public Git tree | 30 of 43 | the same 13 |

Unpack `seedmatch_records.zip` so that `records/` sits beside `json/` and
all 42 rows but the transcript's verify. The list is written
over the source tree deliberately: a hash list that silently omitted the
records would give a reader no way to check them once they had them.

## What is here, and what is one level away

| | count | where |
|---|---:|---|
| analysis outputs and evaluation records | 13 | `json/`, ships in `release_archive.zip` |
| measurement, analysis and orchestration code | 13 | `code/`, ships in `release_archive.zip` |
| design and results documents | 2 | this directory, ship in `release_archive.zip` |
| adversarial design-audit transcript | 1 | this directory; **excluded** from the release archive --- see below |
| raw per-episode records | 12 | `records/`, **excluded** from the release archive by declaration --- see below |
| retained source checkpoints | 6 | not in the tree at all; published as a release asset --- see below |

### The raw records are a side archive, and the exclusion is declared

The 12 files under `records/` hold 165,465 per-episode records in 58,128,240 bytes of plain JSON. They are
published as **`seedmatch_records.zip`**, a versioned release asset of the
public code repository:

| | |
|---|---|
| bytes | 10,164,095 |
| SHA-256 | `aa1701ebe4fbbd609d49388b1a56c7f1d3e051d8b58cdf6b6bd4955b79b5d3fc` |
| entries | 13 (12 record files and a `README.md`) |

The split is by size and nothing else. Unlike the closure suite's
`.jsonl.gz` records, these are plain `.json` and the packager's recursive
walk would ship them by construction, so the exclusion is **stated** --- in
`RESULT_EXCLUDE_PREFIXES` and in `DROPPED_PAYLOAD`, both in
`paper/is2/tools/make_release_zip.py` --- rather than inherited from an
extension rule. Every number printed in either document is bound to an
analysis json under `json/`, which ships in full; the records are needed
only to re-derive those jsons from scratch.

`SEEDMATCH_RECORDS_MANIFEST.json` lists every member with its size, digest
and record count, and ships **inside** the release, so a reader who obtains
the side archive can verify it member by member instead of trusting one
whole-archive digest. Having the manifest neither proves nor implies
possession of the archive.

### The design-audit transcript stays here and does not ship

`DESIGN_REVIEW_ROUNDS.md` is the transcript of the adversarial audit this
design was revised against. It is a process record rather than a
measurement record, and a package meant to be read cold does not carry
another audit's transcript --- the same rule that excludes the
theory-closure suite's two, enforced by the same gate. What the audit
forced is not lost: `DESIGN.md` section 10 states every change it produced,
and the scope limits it imposed are section 2 of `RESULTS.md`, written
before any number existed. Both ship. The exclusion is declared in
`RESULT_EXCLUDE_PREFIXES` and in `DROPPED_PAYLOAD`, whose reason string is
printed into the archive's own `INDEX.md`.

### One inherited flag, so nobody has to wonder about it

The six records in `json/cifar*_resnet26ttt_s*.json` carry
`"gate_pass": false`. That flag is `train_source.py`'s own aspirational
absolute threshold --- clean accuracy above 0.93 on CIFAR-10 and 0.70 on
CIFAR-100 --- and **no published model meets it either**: the published
records under `experiments/results/m0/` carry exactly the same three flags,
`acc_gate` false everywhere, `rot_gate` true on CIFAR-10 and false on
CIFAR-100. Reproducing the published flag pattern exactly is a result, not
a failure. The gate that governs this suite is the declared comparability
one --- each fresh network inside the published across-seed range, plus a
tolerance of 0.010 --- and `RESULTS.md` Section 11 reports it, network by
network, all six passing. The same distinction, in the same words, is drawn
in the theory-closure suite's `json/P2_SOURCE_GATE.json`.
